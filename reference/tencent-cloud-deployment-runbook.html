Coup Online 上线清单

先私有验证，再按公开发布条件启用固定域名。具体命令和配置以仓库的部署文档为准。

1. 准备服务器

  1. 根据玩家位置、域名和备案要求选择腾讯云服务器地域；官方资料见资源清单。
  2. 选择 Ubuntu 24.04 LTS，设置续费或到期提醒，并将 SSH 访问限制在管理来源。
  3. 按部署文档安装 Docker Engine 和 Compose，并将完整仓库放到服务器。
  4. 保留仓库已有的 .dockerignore、Dockerfile、compose.yaml 和 Caddyfile；不要另建一套部署配置。

2. 私有验证

  1. 按照部署文档启动 app 服务。此阶段仅将应用绑定到服务器的 127.0.0.1:8787，不要开放公网 80、443 或 8787。
  2. 确认本机健康检查 http://127.0.0.1:8787/healthz 返回 ok。
  3. 使用 SSH 端口转发，在浏览器中完成建房、加入、对局和刷新重连测试。

3. 启用固定域名

  1. 确认公开发布所需条件已满足；把域名的 A 记录指向服务器公网 IP。
  2. 在不提交 Git 的 .env 中设置 SITE_DOMAIN=实际域名 和 TRUST_PROXY=1。
  3. 开放公网 TCP 80 和 443，保持 8787 仅绑定服务器本机。
  4. 按照部署文档使用 Compose 的 public profile 启动 Caddy，并确认 https://实际域名/healthz 返回 ok。
只有在域名解析和公网端口配置完成后，Caddy 才能申请公开 HTTPS 证书。不要用服务器 IP 代替 SITE_DOMAIN。

4. 发布与故障定位

  1. 选择没有牌局的时间发布更新；替换应用容器会清空内存中的房间和对局。
  2. 域名无法访问时，依次检查 DNS 记录、80/443 防火墙规则和 Caddy 日志。
  3. 网页无法加载时，检查 Compose 服务状态、应用日志和 /healthz。
  4. 实时交互异常时，检查浏览器里的 /socket.io/ 请求。

5. 项目特有事项

  • 固定域名下，加入链接使用当前网页地址和 ?room=六位房间码；客户端已支持生成该链接。
  • 服务器重启、容器重建和发布版本都会清空房间。
部署命令与配置见仓库部署文档；方案依据见架构决策和资源清单。
