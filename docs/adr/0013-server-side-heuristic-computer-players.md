# Computer Players decide on the server from a client's view, by heuristics

A lone visitor could create a Room but never start a Game, and two or three friends could not reach the four to six seats where Coup plays best. The Host can now fill seats with Computer Players during the Lobby Phase. Three decisions shape how they work.

**They act through the Intent path, inside the server process.** After each change to the Game, the Room schedules one timer per Computer Player that has something to decide, with a random delay. When it fires, the Room calls the same engine function a Human Player's Intent would reach. The phase timeouts that produce a Default Action or Default Choice stay as they are and keep serving Human Players only. A phase timeout closes a whole Interrogation Window at once, so it cannot stand in for one seat that challenges, blocks or passes while the others are still thinking.

**They see only what a Human Player in that seat would see.** The decision function receives the public state, its own Hidden Cards and the public events of the current Game. It never receives the Game state itself, so it cannot read the Deck or another Player's Hidden Cards. The hidden-information boundary of ADR 0002 therefore holds for Computer Players by construction, not by discipline, and a Human Player can trust that a Computer Player's Challenge is a guess.

**They use rule-based heuristics with randomness, not a language model or a search.** Each Computer Player draws a temperament at the start of a Game (how readily it bluffs, challenges and attacks) and remembers that Game's Claims. The goal is a believable opponent, not a strong one.

**Considered Options**: A language model was rejected because every decision would cost money and add seconds of latency to a 20-second window, the site is ICP-filed in mainland China where calling an outside model raises its own compliance questions (compare ADR 0012), and the result could not be tested by self-play. Search (ISMCTS, CFR) was rejected as far more work than "believable" needs, and a strong opponent is a worse practice partner for beginners. Connecting Computer Players as socket clients was rejected because it adds a second process and fake connections only to reach functions the Room can already call. Letting a Computer Player take over the seat of a Human Player who forfeits was left out: it raises who decides when the Human Player reconnects.

**Consequences**: A Room with no Human Player present counts as empty, and a Game is discarded when its last Human Player leaves or forfeits, so Computer Players cannot keep a Room alive on timers. A Computer Player is never the Host. Whether its behaviour is believable is checked two ways: a self-play test holds bluff and Challenge rates inside set bands, and a person plays against it.
