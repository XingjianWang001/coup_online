# 内存状态 + repository 接口（暂不落库）

临时网址 + 临时房间意味着「重启丢局」完全可接受，因此 MVP 不为游戏状态引入数据库的复杂度。但为保留迭代空间，`Room` 在牌局状态变化时经 `GameRepository` 接口写出（`save` / `delete`），今日实现为内存版。目前没有任何地方读回这份状态：牌局始终以 `Room` 内存中的对象为准，同一进程内的断线重连也由 `Room` 完成（凭玩家 id 与重连凭证复用座位）。未来要让牌局挺过服务器重启时，再给接口加读取方法、换 SQLite/Redis 实现。重启服务器后所有房间消失，玩家重新开房即可。

**Considered Options**: 曾考虑现在就上数据库（SQLite）。弃用原因：对「证明概念」阶段是纯负担，无持久化需求却要引入 schema、连接、迁移。
