# 服务器托管 quick tunnel 与加入链接

在保持零注册、临时网址的前提下，把「手动在终端跑 cloudflared 并复制链接」这一步收进应用内：服务器按需 spawn `cloudflared tunnel --url http://localhost:8787`，解析出 `trycloudflare.com` 临时域名后回传给房主，前端拼上房间号后缀（`?room=`）生成可复制链接。

## 决策

- **服务器 spawn 隧道（而非房主手动运行）。** 好处是房主无需离开浏览器、无需安装理解 cloudflared CLI 的参数；服务器拿到域名后可直接回传并缓存为模块级单例，多房间复用。
- **链接格式用 query 参数 `?room=ABC123`。** 弃用路径后缀（`/ABC123`）——当前静态文件服务按路径匹配会 404，需额外加路由；弃用 hash（`#ABC123`）——query 更标准、客户端加载即可解析。
- **打开链接仅预填房间码，不自动加入。** `joinRoom` 需要昵称，自动加入无法绕过昵称输入；预填已达成零摩擦的核心收益，避免扩展加入流程。
- **回环信任边界。** `startTunnel` 仅接受回环来源（`127.0.0.1`/`::1`）的 socket。隧道是服务器级资源，若服务器已被隧道暴露到公网，前端「隐藏按钮」无法阻止恶意客户端直接 emit `startTunnel` 在主机上 spawn 进程，故在服务器侧校验 `socket.handshake.address`。

**Considered Options**: 曾考虑「链接打开后自动加入（复用本地身份重连）」。弃用原因：需扩展加入流程、引入「何时算已就绪」的复杂度，与「零摩擦但保留昵称约束」的目标相比收益有限，属后续可选升级。
